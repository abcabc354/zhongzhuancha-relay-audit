# FAQ

## 这是“检测模型真假”吗？

不是。它检查协议面、能力和可用性，不认证底层权重，也不排除同门型号替换。

## 为什么一个 warn 就掉到 92？

因为主分是维度覆盖度的平均。稳定性只有 3 项，1 个 warn 就是 2/3=67%，再和三个 100% 平均，得到约 92%。见 [评分口径](scoring.md)。

## 协议契约 fail 为什么不扣主分？

主分只回答“能不能用”；协议契约、错误码、包装在附录。它们是证据，不是可用性分数。

## 会保存 API key 吗？

不会。key 从 0600 文件或环境变量读取，报告/证据会脱敏；不要把 key 放进 `config/` 以外的位置，也不要把 `.local.env` 提交到仓库。

## 只有 Chat Completions 的站能测吗？

可以。`--mode auto` 先探 `/responses`，不可用就回退 Chat 套件。

## 为什么命令退出码是 2？

协议面 `inconsistent` 时退出 2，但报告已经生成；CI/脚本可以据此判断，不要误以为没有输出。

## 为什么同一请求 input_tokens 会变？

中转可能在相同请求里注入不同隐藏上下文或命中不同缓存；`usage.stability` 会标 warn。

## `previous_response_id` fail 说明什么？

说明中转不支持 Responses 的续接语义，或没有保留上下文；它属于协议契约附录。

## 可以用在商业项目吗？

代码是 MIT；报告只描述协议面，不构成服务商质量/充值建议。使用前请自行评估目标和合规要求。
