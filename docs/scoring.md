# 评分口径

## 主分

主分只看四个维度：

| 维度 | 含义 |
|---|---|
| 稳定性 | Responses/Chat 面可用、同一请求用量稳定 |
| 对话 | attribution、final_answer、cache、verbosity |
| 能力 | 视觉、工具、结构化、reasoning 缩放 |
| 目录 | `/models` 抽检型号存活 |

每个维度：

```text
coverage = round(100 * pass / (pass + warn + fail))
```

`info` 不计入；没有可计项时为 `n/a`。

总分：

```text
overall = round(sum(各维度 coverage) / 非 n/a 维度数)
```

等级：

| 覆盖度 | 等级 |
|---|---|
| ≥ 90 | A |
| ≥ 70 | B |
| ≥ 50 | C |
| < 50 | D |

## 例子

```text
稳定性 2/3 = 67%
对话   4/4 = 100%
能力   4/4 = 100%
目录   1/1 = 100%

overall = (67 + 100 + 100 + 100) / 4 = 91.75 → 92%
```

所以一个 warn 在只有 3 项的小维度里会拉低约 8 分；这是“覆盖度”口径的结果，不是隐藏权重。

## 附录

包装、协议契约、错误码放在附录：

- 不计入主分；
- 单独显示 `pass%` / `fail%`；
- 硬伤数来自其中 `fail` 的检查码。

这样能避免“协议洁癖”直接误杀一个能用的站，同时保留证据。
